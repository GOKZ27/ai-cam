# AGENTS.md — AI Cam

Laravel 13 (PHP 8.3) single-page app. The browser camera captures frames, posts them to Laravel, and Laravel proxies to a separate Python service for object detection and vision description. UI and text-to-speech output are Indonesian.

## Architecture / wiring

- Laravel does no AI itself. `app/Http/Controllers/AiCamController.php` validates the upload and forwards it (`Http::attach`) to the Python service.
- Python service: `python-service/main.py` (FastAPI) serves `/detect` (YOLO), `/describe` (vision), `/health`. Code defaults are `yolo11s.pt` @ `YOLO_IMGSZ=960`, `YOLO_CONF=0.35`; `python-service/.env.example` (and the local `.env`) pin `yolo11s.pt` @ 640 with `YOLO_CONF=0.4`, `YOLO_IOU=0.6`, so running values can differ from code defaults. `YOLO_IMGSZ` is clamped to a multiple of 32. Pick model/imgsz with `python-service/bench_yolo.py` (measures ms/run on this CPU-only box). `/describe` uses Gemini cloud when configured, otherwise Ollama `qwen2.5vl:3b`.
- Vision provider is chosen by `AI_VISION_PROVIDER` (`auto` default, `gemini`, `ollama`). With `auto`/`gemini`, `/describe` uses Gemini when `GEMINI_API_KEY` and `GEMINI_MODEL` are set, and falls back to Ollama when `AI_VISION_FALLBACK` is on. The response includes `provider`, `model`, and `fallback_used`; never present Ollama output as Gemini.
- The Gemini key lives only in the Python backend environment or `python-service/.env` (gitignored). It must never reach Blade/JS/URLs or logs.
- Service URL comes from `config('services.ai_cam.python_url')`, backed by `AI_CAM_PYTHON_URL` (default `http://127.0.0.1:8001`) in `config/services.php`, so it is safe with `php artisan config:cache`.
- Frontend is `resources/views/ai-cam.blade.php`: all HTML/CSS/JS is inline. `resources/js/app.js` is empty and the page does not use `@vite`, so no JS build is required to run the app.
- In realtime mode the page auto-calls `/api/ai-cam/detect` (~1.2 s) and `/api/ai-cam/describe` (default 10 s, user-configurable) without any button press. Vision requests never overlap (next run is scheduled only after the previous finishes); YOLO is throttled while a vision call is in flight. Detection results are spoken immediately (throttled by `DETECT_SPEECH_COOLDOWN`), independent of vision state; vision output is spoken with priority.
- The page includes a "Diagnostik Sistem" panel (`#diagRun` → `runDiagnostics`) that times server, camera, YOLO, vision, and TTS, marks each OK/warn/error against `DIAG_OK`/`DIAG_WARN` thresholds, and summarizes which stage is "belum maksimal". It uses a synthetic image when the camera is off (consumes one vision request).

## Commands

- First-time setup: `composer setup`.
- Dev (Laravel server + queue + vite): `composer dev` (wraps `artisan dev`; inspect with `php artisan dev:list`).
- Realtime needs a concurrent web server. The built-in `php artisan serve` is **single-threaded** and blocks `/detect` behind a slow `/describe`; it also ignores `PHP_CLI_SERVER_WORKERS` unless `--no-reload` is passed. Run `PHP_CLI_SERVER_WORKERS=4 php artisan serve --no-reload` (Windows: set `$env:PHP_CLI_SERVER_WORKERS=4` first). `ServeCommand.php:120` warns "Only creating a single server" otherwise.
- Python service is **not** started by `composer dev`. Start it separately: from `python-service/`, use its existing `.venv` and run `uvicorn main:app --port 8001`. Install/refresh its deps with `python-service/.venv/Scripts/python.exe -m pip install -r python-service/requirements.txt`. `/describe` needs Ollama (`qwen2.5vl:3b`) for the local path and/or `GEMINI_API_KEY`+`GEMINI_MODEL` for the cloud path (copy `python-service/.env.example` to `python-service/.env`).
- Pick a working Gemini model: `python-service/.venv/Scripts/python.exe python-service/list_gemini_models.py` lists models for your key (never prints the key). Do not hardcode guessed names; some names (e.g. `gemini-2.5-*`) can return 404 for new keys, in which case Gemini's error points at the current replacement.
- Tests: `php artisan test` or `composer test` (PHPUnit, not Pest). Single test: `php artisan test --filter=TestName`. Uses in-memory SQLite. Python unit tests (no network): `python-service/.venv/Scripts/python.exe -m unittest test_gemini_mock` from `python-service/`. Speech de-dup JS test: `node tests/js/speech-dedupe.test.mjs`.
- Formatting: `./vendor/bin/pint` (Laravel preset; no `pint.json`).
- YOLO tunables (env, read by `python-service/main.py`): `YOLO_MODEL`, `YOLO_IMGSZ` (multiple of 32), `YOLO_CONF`, `YOLO_IOU` (NMS), `YOLO_MAX_DET`, `YOLO_AGNOSTIC_NMS`, `YOLO_THREADS` (0 = torch default), `YOLO_PRELOAD` (load model at startup; on by default). `python-service/bench_yolo.py [foto.jpg] [runs]` benchmarks models/imgsz; on this CPU-only box yolo11n@640 ≈ 250 ms, yolo11s@640 ≈ 470 ms, yolo11n@960 ≈ 460 ms, yolo11s@960 ≈ 860 ms, yolo11m ≈ 1.3–2.3 s (detect loop runs every 1.2 s). The frontend `/detect` capture is 960px/JPEG q0.7 so higher `YOLO_IMGSZ` still has detail; the box overlay draws every box the server returns, while the object list/speech filter at frontend `CONF_MIN` (0.5).
- Vision tunables are env vars read by `python-service/main.py`: `AI_VISION_PROVIDER`, `AI_VISION_FALLBACK`, `GEMINI_MODEL`, `GEMINI_FALLBACK_MODELS`, `GEMINI_TIMEOUT`, `GEMINI_MAX_OUTPUT_TOKENS`, `GEMINI_JSON_MODE`, `GEMINI_THINKING_LEVEL`, `GEMINI_THINKING_BUDGET`, `GEMINI_RETRIES`, `GEMINI_RETRY_DELAY`, `VISION_MAX_SIDE`, `VISION_JPEG_QUALITY`, `LOW_LIGHT_THRESHOLD`, `YOLO_HINT_CONF`, `OLLAMA_URL`, `OLLAMA_MODEL`, `OLLAMA_SEED`, `OLLAMA_TIMEOUT`, `LOG_LEVEL`. `main.py` loads `python-service/.env` itself via `load_env_file` **without** overriding variables already set in the process env. `GEMINI_FALLBACK_MODELS` is a comma-separated list tried (in order) after `GEMINI_MODEL` on quota/error, before Ollama. The free tier allows very few requests/day per model (e.g. 20/day for `gemini-3.8-flash`), so a lite fallback (e.g. `gemini-3.5-flash-lite`) keeps Gemini in play; enable billing for continuous use. Manual vision test procedure: `python-service/test_describe.py` (needs sample images in `python-service/test-images/`, which is not committed).

## Gotchas

- Routes exist only in `routes/web.php`: `GET /ai-cam`, `GET /api/ai-cam/health`, `POST /api/ai-cam/detect`, `POST /api/ai-cam/describe`. There is no API routes file; keep new endpoints there.
- Python is not on the global PATH (`python` fails). Use the interpreter inside `python-service/.venv`.
- `CLAUDE.md` is an untouched Laravel Boost bootstrap file; it tells agents to run `composer require laravel/boost --dev` + `boost:install`. Boost is **not** installed here and the app doesn't need it — ignore that instruction.
- `composer setup` / `composer dev` run Vite/npm, but `ai-cam.blade.php` never loads `@vite` and `resources/js/app.js` is empty, so the build output is unused. No asset build is required to run the app.
- `python-service/.env` (gitignored) holds the real `GEMINI_API_KEY` and model choices; never print or commit it. `.env.example` has only placeholders, and its YOLO/Gemini model names are examples.
- YOLO confidence is a detection score, not the vision model's certainty. Keep the two distinct in UI copy; never present a fabricated accuracy percentage.
